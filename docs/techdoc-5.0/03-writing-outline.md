### 5.6 音频处理与实时分片转写（1.5–2 页，独立流程图）

必须覆盖：实时会话创建 → 分片上传 → 逐片 ASR → 分片失败重试 → 时间偏移（`offset_seconds`）→ 标记（重点/决议/疑问）→ 结束合并 → 转写编辑 → 用户确认 → 生成会议记录。**明确：分块上传 + 逐片转写，不是 WebSocket/SSE 流式传输。**

## 四、创新点写作要求（不得把"使用某技术"当创新）

每个创新点必须写清：**解决的实际问题 → 采用的具体机制 → 代码实现位置 → 与普通实现相比的价值 → 验证情况与局限**。示例（正文按此展开）：

- 权限下推 RAG：问题=越权分块可能进入应用层；机制=SQL 先按 `user_id` 过滤再算余弦，材料/知识库分 scope；位置=`ai/rag/retriever.py`；价值=可测、可审计；局限=全表拉取、未启用 ANN。
- LLM BYOK + 零回退 + 探测容错：问题=团队垫付 Token、密钥风险；机制=Fernet 密文、掩码、`probe`（429 放行标记）、SSRF 校验、`ALLOW_GLOBAL_FALLBACK=false` 且仅作用 LLM；位置=`model_config_service.py`/`crypto.py`/`url_validation.py`；价值=成本边界与合规；局限=密文入平台库。
- 候选—确认—状态机：问题=AI 误落地；机制=AI 只产候选，确认后才转任务，后端状态机强制；位置=`action_item_service.py`/`task_service.py`；价值=防脏数据；局限=仅覆盖已建模流转。
- 分片边录边转：问题=长会议无法等待整段转写；机制=分块上传+逐片 ASR+失败不中断+分段标记+结束合并；位置=`audio_service.py`；价值=边录边出文本、单片可重试；局限=非流式。
- 协议抽象 + Mock：问题=无模型/无库难测；机制=`httpx.BaseTransport` + `Retriever` Protocol；位置=`tests/conftest.py`；价值=可测；局限=不验证真实效果。

应用创新点：会前/会中/会后闭环、材料与知识库分 scope、行动项确认转任务幂等、用户记忆按用途注入、实时转写工作流、本地会议工作区——同样按上述五要素写，不得只写"使用了 RAG/大模型"。
