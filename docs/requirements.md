# 需求说明

## 一、项目定位

OpenMIND 是面向**个人参会者**的「AI 会议个人助理」，围绕会前准备、会中记录、会后纪要与个人任务跟进，构建可闭环的个人会议工作流。

服务对象是单个参会人（而非团队协作平台），因此第一版不做多人实时协作、会议主持、共享空间与组织权限体系。

## 二、MVP 闭环

```text
创建会议 → 导入资料 → AI 理解与检索 → 会前准备
   → 会中记录与问答 → 生成纪要 → 提取行动项 → 个人任务跟进
```

闭环成立的判定标准：一次真实会议从「建会」走到「行动项转为个人任务并被跟进」，全程数据可追溯、状态由后端控制、关键结果经用户确认。

## 三、功能需求

| 模块 | 阶段 | 内容 | 负责 |
| --- | --- | --- | --- |
| 基础工程 | M00 | 前后端骨架、数据库与迁移、Docker Compose、CI、协作规范 | A |
| 用户认证 | M01 | 注册、登录、退出、当前用户 | A |
| 会议管理 | M02 | 会议列表、创建、详情、编辑、删除、归档 | A |
| 会议资料 | M03 | 上传/删除材料、解析与处理状态、资料索引 | A、B |
| 模型与检索 | M04、M05 | Embedding、向量检索、RAG 问答 | B |
| 会前准备 | M05 | 会前摘要、准备清单、编辑与确认 | B、C |
| 会议记录 | M06 | 会议记录增删改查、标记、音频转写（扩展） | A、C |
| 纪要与行动项 | M07 | 生成纪要、提取候选行动项与未解决问题、人工确认 | A、B、C |
| 个人任务 | M08 | 行动项转任务、任务清单、状态流转、撤销 | A、C |
| 异常与联调 | M09 | 异常处理、权限校验、部署与端到端测试 | 全员 |

详细任务拆分见 [`module-task-plan.md`](module-task-plan.md)。

## 四、关键业务约束

1. **个人数据隔离**：用户只能访问自己拥有的会议、资料、记录、任务与问题。
2. **原始数据与 AI 结果分离**：AI 产出独立存储，不覆盖用户原文。
3. **候选与确认分离**：纪要、行动项、准备清单必须经用户编辑确认后才成为正式结果。
4. **状态由后端控制**：前端不得通过直接改写状态字段绕过业务规则或权限。
5. **可追溯**：个人任务必须能回溯到来源会议与行动项。
6. **密钥不下发**：LLM / Embedding 密钥仅存在于服务端环境变量。

## 五、非功能需求

| 项目 | 要求 |
| --- | --- |
| 权限 | 所有资源访问按当前用户校验，越权返回统一错误码 |
| 错误处理 | 统一响应体 `{ status, error_code, message }`，见 [`api.md`](api.md) |
| 错误码 | 前端可按 `error_code` 做差异化提示 |
| 幂等与重试 | AI 调用标注 `MODEL_TIMEOUT` 等可重试错误 |
| 数据结构变更 | 必须附带 Alembic 迁移文件 |
| 性能（MVP） | 常规列表与详情接口满足交互可感知流畅；检索与生成类接口允许异步或较长等待并展示进度 |
| 隐私 | 不提交真实会议资料到仓库；`storage/` 仅本地持久化 |

## 六、明确不做（第一版范围外）

- 多人实时协作、共享会议空间、组织与团队权限
- 会议主持、议程编排、投票、录制上传与云端转写服务
- 移动端 App、离线模式、浏览器插件
- 多语言界面
- 任何自动化部署流水线（CI 仅做检查）

## 七、验收标准

- `docs/api.md` 约定的接口全部实现，OpenAPI 可自解释。
- 端到端走通「建会 → 传资料 → 会前准备 → 记录/问答 → 纪要 → 行动项 → 任务」全流程。
- 越权访问、非法状态流转、AI 超时等异常场景均有明确错误码。
- 后端 `ruff check .`、`pytest` 与前端 `typecheck`、`lint`、`test`、`build` 全部通过。
