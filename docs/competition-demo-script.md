# OpenMIND 演示视频字幕稿（代码核实修正版）

> 用途：传智杯 AI Web 赛道演示视频口播稿。所有表述已对照 `backend/`、`frontend/` 现状代码核实；标注【修正】处为相对初稿字幕的口径调整，录制时以本稿为准。
> 拍摄顺序：登录 → 主页 → 模型配置 → 记忆中心 → 知识库 → 功能链路 → 资料预处理 → 实时转写 → 会后智能处理 → 会议管理 → 任务管理 → 项目架构 → 亮点创新 → 不足与演进 → 部署地址。
> 时长目标：5–8 分钟；普通话讲解，可配字幕。

## 口径修正速查（录制前核对）

| 编号 | 初稿说法 | 修正后说法（与代码一致） |
| --- | --- | --- |
| A | MD5 去重 | 文件内容摘要为 **SHA256**，另加索引环境指纹；不是 MD5 |
| B | 会话短期记忆保存任务快照、跨设备恢复 | 会话与消息在服务端落库、可跨设备取回；Agent 会话问答默认注入最近有限轮历史（见 I），短期记忆是留存 + 有限上下文，不等于全量对话连续 |
| C | Top-K 搭配相关性二次 Judge 全量过滤 | Top-K 取候选后，**仅在 top1 低于阈值的低分带**交 LLM Judge 复核 top3；Judge 不可用时回退分数判定，不阻断检索 |
| I | 对话历史默认不注入推理上下文 | Agent 会话问答**默认注入最近 6 条、≤3000 字符**的已完成对话历史，可由 `include_history` 关闭；普通会议问答接口仍为单轮；历史只作参考，结论须由资料支撑 |
| D | 基于 WebSocket 流式接收音频 | 音频为 **MediaRecorder 分段 + HTTP 分片边录边传**（start/chunk/finish）；**SSE 只用于问答与 Agent 文本流式**，后端无 WebSocket 音频通道 |
| E | 本地文件夹双向自动同步、免去手动重复上传 | 拉取方向自动增量；**回写与删除是待确认项**，用户确认后才执行；不是后台全自动双向推送 |
| F | 任务管理页统一查看 Agent 运行记录、步骤日志与待确认 | 任务页是**个人业务任务**（行动项转任务）；Agent 运行记录/步骤/待确认在 Agent 对话与转写流程内，由独立接口提供 |
| G | 灵活切换 LLM 与向量模型 | **LLM 支持用户自备与切换**；**Embedding 向量模型由服务端全局统一配置**，用户侧不可自备或切换 |
| H | 多模态 AI 能力 | 当前多模态**仅覆盖语音转写（ASR）**；无图像、视频、视觉大模型能力，讲解时不要扩展承诺 |

## 1. 登录页（约 25 秒）

**画面**：打开登录页，输入评审测试账号登录，跳转主页。

**口播词**：
> 欢迎来到 OpenMIND，一款面向个人参会者的 AI 会议助理。项目围绕会议全流程，提供资料管理、实时录音转写、会后纪要与个人任务跟进能力。登录采用 JWT 鉴权，进入后所有数据按本人账号隔离。

## 2. 主页（约 40 秒）

**画面**：展示主页横幅、会议统计卡片、最近会议列表与待办任务入口；点击「新建会议」可创建。

**口播词**：
> 主页是项目的总入口。顶部汇总今日会议数与待办任务数，下方展示最近会议和待办事项，所有功能从这里进入。页面的会议、待办统计都来自后端真实接口，不是静态演示数据。统一的请求会经过后端公共调度底座，复用同一套鉴权、权限校验、日志记录与 SSE 实时推送能力。

## 3. 模型配置窗口（约 35 秒）

**画面**：打开模型配置弹窗，展示 LLM 的服务地址、密钥、模型名，以及用途级模型选择。

**口播词**：
> 模型配置窗口支持用户自备大模型（BYOK）。LLM 采用 OpenAI 兼容协议接入，适配不同服务商，可在会话内切换推理模型，也支持按用途选择不同模型。密钥在服务端用 Fernet 加密存储，接口只返回掩码，不下发到前端。
>
> 需要说明的是：Embedding 向量模型由服务端全局统一配置，保证向量维度与索引一致，用户侧不提供自备入口。

## 4. 记忆中心窗口（约 50 秒）

**画面**：打开记忆中心，展示用户角色、工作场景、表达偏好、默认纪要模板；说明三层记忆结构。

**口播词**：
> 这里是记忆中心。项目采用三层分层记忆体系：
> 第一层是长期实体记忆，由用户手动维护角色、工作场景、表达偏好和默认纪要模板，注入上下文时有总长上限，避免挤占会议业务资料；
> 第二层是会话短期记忆，会话与消息在服务端落库，换设备登录可以取回记录；
> 第三层是 RAG 向量库，作为长期语义记忆。
>
> 在多轮对话上，Agent 会话会默认带上最近几轮已完成的对话作为上下文，按条数和字符双重预算裁剪，并过滤确认门提示与失败消息；历史只帮助理解指代，结论仍须由会议资料支撑。普通会议问答链路当前仍为单轮。

## 5. 知识库窗口（约 45 秒）

**画面**：展示会议材料与个人知识库两个范围；进入一次问答，展示检索来源片段。

**口播词**：
> 知识库承载 RAG 检索能力。检索分为会议材料和个人知识库两条链路，在数据库查询阶段就按本人账号做权限隔离，互不混检。
>
> 检索流程先按 Top-K 取候选并做相似度阈值过滤；当 top1 分数处于低分带时，再把 top3 候选交给 LLM 相关性 Judge 复核，判无关则整体拒答；Judge 不可用时回退到分数判定，不阻断主链路。这样可以减少无关片段干扰，回答同时标注来源。

## 6. 功能链路页（约 30 秒）

**画面**：展示会前、会中、会后三个阶段的入口与流程步骤条。

**口播词**：
> 产品覆盖会议完整业务链路：会前上传资料、生成准备素材；会中实时录音转写、记录与问答；会后自动生成纪要、提取行动项，并转成个人任务跟进，一站式完成会议处理。

## 7. 资料预处理页（约 40 秒）

**画面**：上传一份 PDF/DOCX/TXT，展示解析、分块、向量化入库的进度与结果。

**口播词**：
> 资料预处理模块负责文档解析、内容去重、文本分块和向量化入库。文件内容用 SHA256 计算摘要，配合索引环境指纹判断是否需要重新解析；分块按句子边界切分并保留重叠区间；空内容和解析失败的文件不进入向量库，作为基础脏数据兜底，为上层 RAG 提供标准化素材。

## 8. 实时录音转写（约 55 秒）

**画面**：进入实时转写页，开始录音，分段上传并看到逐段转写结果；展示一段待确认转写，确认后进入纪要流程。

**口播词**：
> 实时录音转写在浏览器端用 MediaRecorder 分段采集音频，通过 HTTP 分片接口边录边传；长音频进入后端异步任务队列，由独立 worker 认领执行。队列内置心跳与僵尸任务回收机制，避免长任务卡死。
>
> 转写结果必须经过确认门，用户确认后才触发纪要草稿生成；AI 产出只作为候选，不会覆盖原始记录。问答和 Agent 的文本回答走 SSE 流式推送，和音频上传是两条通道。

## 9. 会后智能处理（约 55 秒）

**画面**：展示润色、精简、改写等轻量操作，以及纪要生成、行动项抽取等复杂任务；标注确认门与步骤记录。

**口播词**：
> 会后智能处理基于自研的声明式 Workflow 引擎，不依赖第三方编排框架。工具由后端意图路由统一调度，而不是交给大模型自行挑选工具。
>
> 任务按复杂度分两条链路：润色、精简、改写这类轻量任务走单步快捷链路；纪要、待办抽取这类复杂任务走多步编排，支持条件分支跳转、人工确认门、步骤级重试与步数、时长预算熔断，工作流状态和当前步骤会落库保存快照。

## 10. 会议管理页 · 本地工作区同步（约 50 秒）

**画面**：绑定本地文件夹，展示远端会议资料、本地文件与基线对账；拉取自动完成；本地新增/修改项显示为待确认回写，点击确认后上传。

**口播词**：
> 会议管理模块支持与本地文件夹对接。前端通过浏览器文件系统访问 API，在用户授权后扫描本地目录，与远端快照、上次基线做三方对账，按大小、修改时间和哈希识别增量。
>
> 拉取方向自动增量同步；本地新增或修改产生的回写、以及删除操作，都会先列为待确认项，由用户确认后再执行，并带乐观锁和幂等键防止重复与冲突。同步基线存在浏览器本地，会议目录下写一份清单文件作为可移植镜像。

## 11. 任务管理页（约 35 秒）

**画面**：展示全部任务、待处理、进行中、已完成、已归档筛选；打开一条任务查看状态与撤回/取消操作。

**口播词**：
> 任务管理页集中跟进由会议行动项转化来的个人业务任务，支持按状态筛选、更新进度、撤回归档和取消。Agent 侧的运行记录、步骤日志和待确认操作，保留在对话与转写处理流程中，可通过运行记录与步骤轨迹接口追溯；两类数据在产品定位上分开管理。

## 12. 项目架构（约 50 秒）

**画面**：展示整体架构图：前端页面 → 公共调度底座 → Workflow 引擎 → 三层记忆与预处理流水线 → ASR 转写 → 模型层。

**口播词**：
> 这是 OpenMIND 的整体架构。最上层是前端交互页面，包含演示用到的全部页面；所有请求统一进入公共调度底座，由意图路由分发，统一处理鉴权、权限、流式推送和日志。
> 底座下层是自研 Workflow 引擎，按任务复杂度差异化编排：轻量任务单步执行，纪要、转写等复杂任务多步编排，内置确认门和熔断保护。
> 配套三层记忆：实体记忆存用户偏好，会话记忆留存任务快照，向量库 RAG 作为长期语义记忆；预处理流水线负责解析、去重、分块，为 RAG 提供素材。
> ASR 模块通过兼容接口对接语音转写服务，输出送入工作流；模型层 LLM 走 OpenAI 兼容协议，向量模型由服务端统一配置。

## 13. 总结亮点与创新点（约 35 秒）

**画面**：逐条列出亮点卡片，配合对应页面回放。

**口播词**：
> 项目亮点可以概括为五点：一是公共调度底座加差异化 Workflow 编排，轻量与复杂任务分流；二是三层记忆体系结合 RAG 检索；三是带确认门、重试与预算熔断的可控工具调度；四是长音频异步队列配合心跳与僵尸回收；五是多用户数据在查询阶段前置隔离。

## 14. 不足与后续演进（约 30 秒）

**画面**：展示当前问答界面与受限说明。

**口播词**：
> 当前也存在明确局限：多轮历史仅有最近有限轮预算，且只在 Agent 会话问答链路注入，长程指代和跨会议上下文能力仍有限；会议记录只附带最近有限条作为上下文，转写内容不进入向量库。后续计划放宽历史预算、把历史注入扩展到普通问答链路，完善跨会议会话记忆与多轮追问，并继续优化轻量任务链路。

## 15. 部署与演示地址（约 20 秒）

**画面**：展示部署环境信息、访问地址与测试账号入口。

**口播词**：
> 项目基于 Docker Compose 编排数据库、后端与前端，可部署到学生机通过高端口对外访问；评审环境将保持服务可用，并提供评审专用测试账号。完整安装运行指南、环境变量模板和接口文档都在仓库 README 与 docs 目录中。

## 录制注意事项

1. 不要在视频中出现真实模型密钥、数据库密码或 `docker/.env` 内容；演示用配置走环境变量。
2. 截图/录屏中若出现豆包或其他第三方水印，按产品规则不予渲染；空态图标使用项目内置素材。
3. 涉及「进行中会议」时，以后端状态与 `meeting_time` 为准；模型未提供起止时长，不要在画面上编造会议时间段。
4. 被追问 WebSocket、MCP、图像/视频识别、向量模型切换时，按本稿口径如实说明现状，不延伸承诺未实现能力。
5. 被问及对话历史时：说明 Agent 会话默认注入最近 6 条、≤3000 字符的已完成历史，可关闭；普通会议问答接口仍为单轮。不要说「历史完全不进推理」，也不要说成「全量历史连续对话」。
